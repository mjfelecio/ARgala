## Review focus

1. A direct link, stale invitation, changed selection or restored query cannot admit a different destination or start sensors. M4/M5 exercise actual router/focus paths and consume single-use authority.
2. A one-shot fix, replayed timestamp, failed continuous watcher or manual map center cannot unlock AR. M4 checks independent sample time, corroboration and expiry.
3. Camera/ARCore permission or installation activities can interrupt startup. M1/M3 cover delayed native results, deadlines, explicit retry and no duplicate prompt.
4. Looking almost vertically, crossing yaw ±180°, or selecting during motion cannot flip the ring or leave a selected panel continually head-locked. M2 exercises pure geometry and physical rotation/translation separately.
5. Long CJK content, enlarged text, missing glyphs and locale changes cannot lose pages or leak rich content into 2D. M2/M3 exercise actual locales; a native text checkpoint precedes full content work.

### Viro feasibility: suitable candidate, device gate still required

The pinned [Viro 3.0.3 package metadata](https://github.com/ReactVision/viro/blob/v3.0.3/package.json) declares Expo `>=57 <58`, RN `>=0.86 <0.87` and React `>=19`, matching the installed versions. Registry metadata identifies 3.0.3 as the current stable candidate at this review. The blueprint's 2.56.0 reference declares incompatible Expo/RN ranges; do not install it. Peer-range compatibility is not a compiled/runtime result.

Proposed native dependency change, **during M1 only**:

```bash
npx expo install @reactvision/react-viro@3.0.3
```

Pin the resulting dependency exactly and commit `package-lock.json`. Add `['@reactvision/react-viro', { android: { xRMode: ['AR'] }, provider: 'none' }]` to `app.config.ts`; also set navigator provider to `none`. Verify against the [pinned plugin options](https://github.com/ReactVision/viro/blob/v3.0.3/plugins/withViro.ts). Local camera-relative tracking needs no new cloud/VPS/geospatial credential or anchor provider. Do not add Quest/web rendering, microphone, background location or cloud-anchor services.

[Viro's Expo instructions](https://viro-community.readme.io/docs/integrating-with-expo) require a rebuilt native development client. [Expo development-build guidance](https://docs.expo.dev/develop/development-builds/use-development-builds/) also confirms native dependencies require rebuilding. Existing Metro/OTA JavaScript and Expo Go cannot supply Viro's native implementation. Preserve Fabric/New Architecture and Hermes; do not try disabling them to bypass incompatibility.

Specific source risks requiring M1 verification:

- The [3.0.3 Android plugin](https://github.com/ReactVision/viro/blob/v3.0.3/plugins/withViroAndroid.ts) rewrites manifest feature/query arrays and includes Gradle mutations. Verify final generated **and merged** manifests/Gradle, permission blocks, Maps configuration and AR-optional distribution. Config introspection alone does not cover every dangerous mod or merger.
- The [support helper](https://github.com/ReactVision/viro/blob/v3.0.3/components/Utilities/ViroUtils.tsx) does not establish that AR services are installed/current; unavailable native integration must not masquerade as unsupported hardware. Handle supported, unsupported, transient/unknown and integration-unavailable separately through an adapter.
- The [native navigator startup failure handler](https://github.com/ReactVision/viro/blob/v3.0.3/android/viro_bridge/src/main/java/com/viromedia/bridge/component/VRTARSceneNavigator.java) logs ARCore failure without a demonstrated JS error event. Bound startup and provide retry; verify install-declined/outdated-services behavior. Keep camera permission and AR-services installation-attempt state outside the remounting navigator. Preserve an outstanding system-activity attempt; a new native view must not automatically recreate its prompt. Decline/failure requires explicit Retry. If reliable typed readiness cannot be surfaced, add a narrow version-checked patch/Expo native adapter through reproducible configuration, or stop at the spike with evidence. Never parse arbitrary English errors or silently equate timeout with unsupported hardware.
- Native detach disposes the scene. Preserve logical state outside the navigator and reacquire pose after remount; reuse the existing navigation-transition readiness principle rather than assuming focus means a usable camera surface.
